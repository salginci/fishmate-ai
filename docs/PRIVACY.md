# Privacy

A fishing spot is sensitive. Anglers do not publish their marks, and an app
that leaks them is worse than useless — so location is treated as the most
sensitive thing in the product, ahead of email.

## Location

The user picks one of four postures in Settings:

| Setting | Behaviour |
|---|---|
| **Precise** | Full GPS coordinates stored |
| **Approximate** *(default)* | Rounded to 2 decimals (~1 km) **before leaving the device**, and again on the server before insertion |
| **Manual** | Only a spot name the user typed; no device GPS |
| **Don't share** | No device position is ever read or sent |

Three properties worth stating plainly:

1. **Coarsening happens at write time, not display time.** With "approximate",
   the precise value is never persisted anywhere, so there is nothing to leak
   later. Enforced in `FusedLocationProvider`, in the session endpoints, and in
   the `start_fishing_session` tool.
2. **The consent level is stored next to the data** (`location_precision`), so
   we always know what the user agreed to for a given row.
3. **Logs never carry a precise position.** `round_coords()` /
   `Log2.coords()` coarsen to 2 decimals, and the audit trail stores coarsened
   coordinates too — the audit answers "which tools ran", not "where does this
   person fish".

~1 km is enough for weather, wind, wave and sunrise data. It is not enough to
find someone's mark.

## Nothing is shared

There is no social feed, no public catch map, no leaderboard, and no sharing by
default. Sessions, catches and spots are visible only to their owner; every
query filters by the authenticated user, and **no tool accepts a `user_id`
argument**, so there is no code path that could read another account's data.
Tested directly (`test_user_cannot_read_another_users_data`).

## Voice and camera

| | |
|---|---|
| **When** | Only while Fishing Mode is running. Stopping it tears down the microphone, camera and socket. |
| **Where to** | Streamed to Google's Gemini Live API over an encrypted WebSocket. |
| **Stored by FishMate?** | **No.** No audio is recorded. No video is stored. |
| **Camera default** | **Off.** Voice-only until the user opts in. |
| **What the camera sends** | Low-resolution JPEG stills (768 px, q70) at ~0.5 fps — not a video stream. |
| **Transcripts** | Generated by the Live API for the on-screen transcript. Held in memory, capped at 200 lines, not uploaded. |

The foreground-service notification is deliberately unmissable: if FishMate is
listening, there is a notification saying so. We do not pretend to background
listening, and Android would not allow it anyway.

## What leaves the device

| Data | Goes to | Why |
|---|---|---|
| Audio stream | Gemini Live | So it can hear you |
| JPEG frames | Gemini Live | Only while the camera is on |
| Coarsened coordinates | FishMate backend → Open-Meteo | Weather and sea state |
| Catches, sessions, tackle | FishMate backend | Sync across devices, and the memory feature |
| Email + display name | FishMate backend | Account |
| **Photos** | **Nowhere.** Device-local, referenced by URI | No backup path exists yet |

Open-Meteo receives coordinates only — no account identifier, nothing linking a
position to a person.

## Deletion

**Settings → Delete my account and data** calls `DELETE /api/v1/me`, which
hard-deletes the user row. Database cascades remove preferences, tackle,
spots, sessions, observations, weather snapshots, recommendations, catches,
photos, tool audit rows and conversation summaries. It is irreversible and the
app asks for confirmation.

Signing out also clears the local Room database, so the previous angler's catch
history is not visible to whoever signs in next on the same phone.

## Backups

`allowBackup="false"`, with explicit exclusions in
`data_extraction_rules.xml` for cloud backup and device transfer. The local
database holds catch history and spots, and the auth store holds a session
token; neither should ride along in a Google backup. The server is the source
of truth, and signing in restores what the user actually owns.

## AI identification

Species identification is a **suggestion**. The UI labels it with the model's
confidence, shows the visual cues behind it, and always offers "That's correct"
or "Change species". Correcting it clears the model's confidence. The disclaimer
— *AI identification may be incorrect* — is shown on the catch itself, not
buried in a settings page.

## Regulations

FishMate will not state a size limit, closed season, quota or protected status
it cannot cite. When it cannot verify something it says so and names the
responsible authority. See [ARCHITECTURE.md](ARCHITECTURE.md#regulatory-data).

This is a privacy document, but the reasoning is the same: the cost of being
confidently wrong falls on the user, not on us.
